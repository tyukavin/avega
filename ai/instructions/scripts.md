# JavaScript

## 3.1. Формат модулей

- Исходные файлы в `src/js/` — это ESM-модули (`import`/`export`), esbuild собирает их в бандл и изолирует скоуп. Конечный результат оборачивается в IIFE автоматически, в исходниках IIFE не пиши.
- Допустимы build-time-импорты из npm-пакетов и локальных модулей. Runtime-зависимости через CDN запрещены; исключение для Swiper.js описано в разделе 3.6.
- Один модуль должен отвечать за одно законченное поведение и безопасно выполняться на любой странице.
- В начале DOM-модуля найди точку монтирования по смысловому `data-*`-атрибуту и сразу заверши выполнение, если её нет.
- Не создавай глобальные переменные и не добавляй свойства в `window`. Данные, константы и вспомогательные функции держи внутри модуля.
- Глобальные инициализаторы документа, например раннее применение темы, могут не иметь отдельной точки монтирования.
- Предпочитай `const`; используй `let` только для значения, которое действительно переназначается. Не используй `var`.

```js
function initMobilePanel() {
    const mount = document.querySelector("[data-mobile-panel]");
    if (!mount) return;

    // Логика одного компонента.
}

initMobilePanel();
```

## 3.2. Работа с DOM и состояниями

- Используй `data-*` только как контракт JavaScript с разметкой. Визуальное состояние отражай классами `is-*`.
- При изменении состояния синхронно обновляй классы, текст, нативные свойства, ARIA-атрибуты и `inert`.
- Для пользовательских данных используй `textContent`, DOM-методы или безопасные шаблоны. Не вставляй непроверенные данные через `innerHTML` и `outerHTML`.
- Не изменяй DOM повторно, если требуемое состояние уже установлено.
- Обработчики должны быть короткими и называть намерение. Сложную логику выноси в локальные функции.
- Используй делегирование событий для динамических однотипных элементов, когда это упрощает код.
- Не регистрируй один обработчик несколько раз. Удаляй временные слушатели, таймеры и наблюдатели после завершения их работы.
- Не блокируй стандартное поведение браузера без необходимости.

## 3.3. Доступность поведения

- Не имитируй кнопку или ссылку обработчиком клика на `div` или `span`.
- Клавиатурное поведение нативных элементов сохраняй без ручного дублирования.
- После открытия модального окна переноси фокус внутрь, удерживай его в пределах активного диалога и возвращай на вызвавший элемент после закрытия.
- При асинхронном действии показывай понятное состояние загрузки и предотвращай случайную повторную отправку.
- Ошибки и результаты действий должны быть доступны визуально и, при необходимости, объявляться через `aria-live`.

## 3.4. Запросы к бэкенду

- Для JSON POST-запросов используй единую локальную обёртку `jsonRequest`.
- Проверяй `response.ok`; не считай успешным любой ответ, который удалось преобразовать в JSON.
- Обрабатывай отсутствие или невалидность JSON и возвращай пользователю понятную ошибку.
- Ошибки сети и отмену запроса обрабатывай на уровне вызывающего компонента. Состояние загрузки сбрасывай через `finally`.
- Не помещай секреты, токены доступа и чувствительные данные в клиентский код или сообщения ошибок.

```js
const jsonRequest = async (url, payload) => {
    const response = await fetch(url, {
        method: "POST",
        credentials: "same-origin",
        headers: {
            "Content-Type": "application/json",
            Accept: "application/json",
        },
        body: JSON.stringify(payload),
    });
    const data = await response.json().catch(() => ({}));

    if (!response.ok) {
        throw new Error(data.error || "Ошибка запроса");
    }

    return data;
};
```

## 3.5. Раннее применение темы

- Устанавливай тему до первой отрисовки, чтобы исключить мигание. Размещай инлайн-скрипт в `head` до подключения таблиц стилей.
- Приоритет выбора: валидный GET-параметр `theme` → значение `site-theme` из `localStorage` → светлая тема.
- При недоступном `localStorage` страница должна продолжить работу со светлой темой.

```js
(() => {
    const allowedThemes = new Set(["light", "dark"]);
    const requestedTheme = new URLSearchParams(window.location.search).get(
        "theme",
    );
    let theme = allowedThemes.has(requestedTheme) ? requestedTheme : null;

    if (!theme) {
        try {
            const savedTheme = localStorage.getItem("site-theme");
            theme = allowedThemes.has(savedTheme) ? savedTheme : null;
        } catch {
            // localStorage может быть недоступен.
        }
    }

    document.documentElement.dataset.theme = theme || "light";
})();
```

## 3.6. Карусели и слайдеры

- Для каруселей и слайдеров используй Swiper.js. Не создавай собственную реализацию прокрутки, drag-жестов и переключения слайдов.
- Swiper.js является допустимым исключением из общего запрета сторонних runtime-зависимостей. Не подключай библиотеку, если интерфейс можно реализовать обычной прокруткой или CSS без поведения карусели.
- Устанавливай библиотеку через npm и подключай через существующую сборку проекта. Не используй CDN и не добавляй vendor-файлы вручную.
- Импортируй Swiper.js и необходимые стили через точку входа сборки; поиск DOM и инициализацию экземпляра выполняй в отдельном модуле. Build-time-импорт не должен создавать глобальный API.
- Инициализируй каждый слайдер в самостоятельном модуле после проверки его `data-*`-точки монтирования.
- Подключай только необходимые возможности библиотеки и не дублируй её встроенное поведение собственным кодом.
- У слайдера должны быть доступные названия, клавиатурное управление и понятные кнопки перехода. Декоративные иконки внутри кнопок скрывай через `aria-hidden="true"`.
- Автоматическое перелистывание по умолчанию не используй. Если оно требуется, предоставь управление паузой и учитывай `prefers-reduced-motion`.
- Контент должен оставаться читаемым и доступным при ошибке инициализации или отключённом JavaScript.

## 3.7. Поддержка браузеров

- Ориентируйся на поле `browserslist` в `package.json`; не выбирай набор браузеров самостоятельно.
- Перед использованием нового CSS-свойства или Web API проверь его поддержку целевыми браузерами.
- Для критичного поведения предусматривай безопасный fallback. Некритичное улучшение может отсутствовать, если базовый сценарий остаётся доступным.
- Не добавляй полифилл без подтверждённой необходимости и оценки его влияния на размер сборки.
- Не применяй браузерные хаки, если проблему можно решить стандартным API или корректной структурой компонента.

## 3.8. Безопасность клиентского кода

- Не используй `eval`, `new Function`, строковые обработчики событий и исполнение кода из непроверенных данных.
- Не вставляй пользовательские или серверные строки через `innerHTML`, `outerHTML` и `insertAdjacentHTML` без гарантированной очистки.
- Проверяй динамические URL и разрешённые протоколы перед установкой в `href`, `src` и другие URL-атрибуты.
- Не храни секреты, токены доступа и чувствительные пользовательские данные в исходном коде, DOM, URL или `localStorage`.
- Не показывай пользователю необработанный текст серверной ошибки, stack trace и внутренние технические сведения.
- Не отключай встроенные ограничения браузера и политики безопасности ради упрощения реализации.

## 3.9. Progressive enhancement

- Основной контент, навигация и критичные действия должны оставаться доступными без JavaScript, если задача не требует полноценного клиентского приложения.
- JavaScript должен улучшать готовую семантическую разметку, а не создавать критичный контент без необходимости.
- Ссылки и формы должны иметь рабочее базовое поведение до инициализации скриптов.
- Ошибка одного модуля не должна препятствовать работе независимых компонентов.
- Состояние загрузки не должно навсегда скрывать контент при ошибке сети или инициализации.

## Проверка JavaScript

- Убедись, что каждый модуль не создаёт глобальных переменных. Каждый DOM-компонентный модуль должен безопасно завершаться без точки монтирования; глобальные инициализаторы документа проверяй отдельно.
- Проверь, что DOM ищется через `data-*`, визуальные состояния задаются через `is-*`, а классы не используются как JS-хуки.
- Проверь синхронность DOM-состояния, ARIA-атрибутов, текста, фокуса и `inert` после каждого пользовательского действия.
- Убедись, что непроверенные данные не вставляются через `innerHTML` или `outerHTML`.
- Проверь отсутствие повторных обработчиков, забытых таймеров, наблюдателей и временных слушателей.
- Проверь успешный ответ, HTTP-ошибку, сетевую ошибку, невалидный JSON и повторную отправку для интерфейсов с запросами.
- Убедись, что сторонние runtime-зависимости не добавлены. Для реальной карусели допустим только Swiper.js с соблюдением требований раздела 3.6.
- Проверь отсутствие ошибок и необработанных исключений в консоли браузера.
