# Стили

## 2.1. Организация SCSS

- Единственной точкой входа остаётся `src/scss/style.scss`. Подключай зависимости явно через `@use`.
- SCSS-файлы именуй как partials с префиксом `_` (например, `_mixins.scss`). При подключении через `@use` префикс опускай: `@use "base/mixins"` для `src/scss/base/_mixins.scss`.
- Point входа `src/scss/style.scss` — не partial, записывается без `_`.
- Общие настройки, шрифты, базовые стили и утилиты размещай в соответствующих директориях `base` и `global`.
- Стили самостоятельного блока храни рядом с компонентом и подключай из точки входа.
- Не используй глобальные импорты и скрытые зависимости между компонентами.
- Не изменяй normalize/vendor-стили ради локального компонента.

## 2.2. Селекторы и БЭМ

- Стилизуй компоненты классами. Не используй `id`, `data-*` и ARIA-атрибуты как основные CSS-селекторы.
- Не привязывай блок к месту размещения длинными контекстными селекторами. Для варианта внешнего вида используй модификатор.
- Не повышай специфичность без необходимости и избегай `!important`. Исключение допустимо только при документированной интеграции со сторонними стилями.
- Не допускай глубокой SCSS-вложенности. Итоговый селектор должен оставаться коротким и очевидным.
- Через `&` группируй элементы, модификаторы, псевдоклассы и псевдоэлементы только тогда, когда итоговое имя легко прочитать.
- Не стилизуй вложенные теги компонента, если им можно назначить БЭМ-класс.

- Располагай свойства внутри правил в фиксированном порядке:

    1. позиционирование: `position`, `inset`, `z-index`, `order`
    2. блочная модель: `display`, `grid-*`, `flex-*`, `width`, `height`, `margin`, `padding`, `box-sizing`
    3. типографика: `font-*`, `line-height`, `letter-spacing`, `text-*`, `white-space`, `word-break`
    4. оформление: `color`, `background-*`, `border-*`, `border-radius`, `outline`, `box-shadow`, `opacity`
    5. анимация: `transition-*`, `transform-*`, `animation-*`, `will-change`

```scss
.product-card {
    &__title {
        /* Стили элемента. */
    }

    &--featured {
        /* Вариант блока. */
    }
}
```

## 2.3. CSS-переменные и дизайн-токены

- Повторяемые цвета, шрифты, размеры, отступы, радиусы, тени, слои и параметры анимации обязательно задавай нативными CSS-переменными.
- Глобальные токены объявляй в `:root` и называй по назначению, а не по текущему значению: `--color-text`, а не `--color-black`.
- Значения, относящиеся только к одному компоненту, можно объявлять локально в классе блока.
- Не создавай переменную для разового значения, которое не является частью дизайн-системы.
- SCSS-переменные используй только для вычислений, циклов и других задач сборки. Не заменяй ими доступные во время выполнения CSS-токены.

```scss
:root {
    --ease: cubic-bezier(0.2, 0.8, 0.2, 1);
    --header-height: 80px;
    --shell: 1200px;
    --page-gutter: max(40px, calc((100vw - var(--shell)) / 2));
    --mobile-gutter: 16px;
}
```

## 2.4. Общие классы

- Повторяющееся базовое поведение выноси в глобальный класс с названием по назначению, например `button-reset` или `visually-hidden`.
- Глобальный класс должен быть действительно переиспользуемым. Не создавай его для единственного случая или случайно совпавших стилей.
- В глобальном классе оставляй только общее поведение. Размеры, цвета, отступы и внешний вид конкретного блока держи в стилях компонента.
- Не превращай набор утилит в замену семантическим БЭМ-компонентам.

## 2.5. Адаптивность и устойчивость макета

- Сначала обеспечивай корректную работу на узком экране, затем расширяй компоновку медиазапросами.
- Выбирай точки перелома по поведению контента, а не под конкретные модели устройств.
- Используй гибкие размеры, `min()`, `max()`, `clamp()`, Grid и Flexbox. Избегай фиксированных размеров там, где содержимое может измениться.
- Контент не должен обрезаться при увеличении текста и масштабе страницы. Проверяй длинные слова, локализацию и динамические данные.
- Изображения и медиа не должны выходить за пределы контейнера.
- Не маскируй ошибки компоновки глобальным `overflow-x: hidden`.
- Интерактивная область элемента должна быть достаточно большой для точного нажатия на сенсорном экране.

## 2.6. Фокус, движение и пользовательские настройки

- Оформляй заметный `:focus-visible`. Не удаляй `outline` без равноценной замены.
- Не передавай состояние только цветом; используй дополнительный текстовый, графический или структурный признак.
- Проверяй достаточный контраст текста, элементов управления и состояния фокуса в каждой теме.
- Для существенных анимаций учитывай `prefers-reduced-motion` и отключай или сокращай движение.
- Анимируй преимущественно `transform` и `opacity`. Не добавляй анимацию без функциональной пользы.

## 2.7. Светлая и тёмная темы

- Добавление темы опционально. Если тема нужна, поддерживай `light` и `dark` через `data-theme` на элементе `html`.
- Светлые значения задавай базовыми токенами. В `html[data-theme="dark"]` переопределяй токены тёмной темы в одном месте.
- Компоненты должны использовать токены вместо собственных жёстко заданных цветов.
- Точечные селекторы темы допустимы только когда замены токена недостаточно.

```scss
:root {
    color-scheme: light;
}

html[data-theme="dark"] {
    color-scheme: dark;
    --color-text: #f5f5f5;
    --color-background: #121212;
}

html[data-theme="dark"] .review-card {
    /* Только необходимое исключение. */
}
```

## 2.8. Соответствие макету

- Реализуй размеры, сетку, типографику, цвета и состояния по исходному дизайну. Не подбирай значения приблизительно, если их можно определить из макета или существующих токенов.
- Проверяй компонент на всех контрольных ширинах, представленных в макете, и между ними.
- Учитывай все предусмотренные состояния: default, hover, focus, active, disabled, loading, error, empty и заполненное состояние.
- Не исправляй локальное расхождение позиционированием, отрицательными отступами или жёсткими размерами, если это нарушает компонент при другом содержимом.
- Если макет противоречит семантике, доступности или техническим ограничениям, сохраняй доступное поведение и явно сообщай о расхождении.

## Проверка стилей

- Проверь явные `@use`, расположение стилей в правильном слое и отсутствие скрытых зависимостей между компонентами.
- Проверь селекторы: отсутствие стилизации по `id` и `data-*`, лишней специфичности, глубокой вложенности и необоснованного `!important`.
- Убедись, что повторяемые дизайн-значения вынесены в CSS-переменные, а компоненты используют токены вместо дублирующихся значений.
- Проверь обоснованность глобальных классов и отсутствие утилит, созданных ради единственного случая.
- Проверь макет на узком и широком экране, при длинном контенте, увеличении текста и масштаба страницы. Горизонтальная прокрутка не должна скрывать ошибку компоновки.
- Проверь состояния `hover`, `focus-visible`, `active`, `disabled`, ошибки и загрузки, если они предусмотрены компонентом.
- Проверь контраст, признаки состояния без опоры только на цвет и поведение анимаций при `prefers-reduced-motion`.
- Если используются темы, проверь обе темы: токены, нативные элементы, контраст, изображения, состояния и отсутствие мигания при загрузке.
