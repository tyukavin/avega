# Разметка

## 1.1. Семантика документа

- Выбирай HTML-элемент по смыслу, а не по внешнему виду. Используй `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`, списки, таблицы и элементы форм вместо универсальных `div` и `span`.
- На странице должен быть один `main` и один основной `h1`. Остальные заголовки выстраивай в последовательную иерархию без пропуска уровней.
- У `section` и `article` должен быть доступный заголовок. Если самостоятельный раздел и заголовок не нужны, используй `div`.
- Если на странице несколько `nav`, каждому задай различимое доступное имя через `aria-label` или `aria-labelledby`.
- Для действия используй `button`, для перехода — `a` с корректным `href`. Всегда указывай `type` у кнопок.
- Однотипные сущности оформляй через `ul` или `ol`, пары «термин — описание» — через `dl`.
- Табличные данные размечай через `table`. Добавляй `caption`, заголовочные ячейки `th` и подходящий `scope`, когда контекст не очевиден.
- Указывай язык документа через `lang`. Машиночитаемые даты оформляй через `time` и `datetime`.

## 1.2. БЭМ и классы

- Используй классы как основной способ стилизации компонентов.
- Именуй сущности по схеме `block`, `block__element`, `block--modifier`, `block__element--modifier`.
- Все имена классов должны быть смысловыми и записываться в `kebab-case`: `product-card`, а не `white-box`.
- Блок должен быть самостоятельным и пригодным для повторного использования. Элемент не существует вне блока.
- Не создавай «элементы элементов»: `card__title`, а не `card__header__title`.
- Модификатор всегда используй вместе с базовым классом: `button button--primary`.
- Состояния интерфейса обозначай классами `is-*`: `is-active`, `is-open`, `is-loading`.
- Точки подключения JavaScript задавай смысловыми `data-*`-атрибутами. Не используй классы как JS-хуки.
- `id` применяй для якорей и связей доступности, но не для стилизации.
- Компонент размещай в `src/components/bem-blocks/<block>/`. Связанные HTML, SCSS и JavaScript храни рядом, если они принадлежат только этому блоку.
- HTML-компонент подключай в макет или страницу через `@@include` с синтаксисом `gulp-file-include`:
    ```html
    @@include('components/bem-blocks/button/button.html')
    ```
    Частичные файлы из `src/components/` (включая `page-blocks/`) считаются partial-шаблонами и отдельно в `build` не копируются. Страницами становятся только файлы на верхнем уровне `src/`, содержащие теги `<html>`.

```html
<article class="product-card product-card--featured">
    <h2 class="product-card__title">Название товара</h2>
    <button class="product-card__button" type="button" data-product-action>
        Купить
    </button>
</article>
```

## 1.3. Атрибуты и форматирование HTML

- Короткий читаемый тег записывай в одну строку.
- При переносе оставляй первый атрибут рядом с именем тега, остальные располагай по одному на строку с отступом в четыре пробела.
- Закрывающий `>` оставляй в строке последнего атрибута.
- Соблюдай одинаковый порядок атрибутов: `class`, `id`, `href`/`src`/`type`, `name`/`value`, `data-*`, `aria-*`, остальные атрибуты.
- Не добавляй пустые контейнеры и атрибуты без функционального или семантического назначения.
- Комментарии используй только для структуры шаблона или неочевидных ограничений. Не комментируй очевидную разметку.

```text
<button class="theme-switch__button"
    type="button"
    data-theme-control="dark"
    aria-pressed="false"></button>
```

## 1.4. Изображения и медиа

- Каждый `img` должен иметь `alt`. Для содержательного изображения кратко передавай его смысл; для декоративного используй `alt=""`.
- Не дублируй в `alt` соседнюю подпись или доступное имя элемента.
- Указывай `width` и `height`, чтобы браузер резервировал место и не происходил сдвиг макета.
- Для изображений вне первого экрана используй `loading="lazy"`. Не применяй ленивую загрузку к ключевому изображению первого экрана.
- Сборка автоматически создаёт WebP и AVIF для каждого изображения в `src/img/`. Когда нужна ручная адаптивная вёрстка, используй `<picture>` с `<source type="image/webp">` и `<source type="image/avif">`, ссылаясь на те же имена с расширением `.webp`/`.avif`.
- Декоративные SVG внутри подписанных элементов скрывай от скринридеров через `aria-hidden="true"`.
- Если изображение является единственным содержимым ссылки или кнопки, у интерактивного элемента должно быть доступное имя.

## 1.5. SVG в CSS и спрайтах

- SVG-иконки из `src/svg/sprite/` собираются в symbol-спрайт `build/img/sprite.svg`. Используй `<svg><use href="img/sprite.svg#icon-name"></use></svg>`.
- SVG из `src/svg/css/` преобразуются в data URI и доступны через CSS-класс `.--svg__имя-файла` (сгенерированное имя: `--svg__название`). Не редактируй сгенерированные CSS-классы вручную.
- Для декоративных SVG внутри спрайта указывай `aria-hidden="true"` на корневом элементе.

## 1.6. Формы

- Каждое поле связывай с видимым `label` через `for` и `id`.
- Указывай подходящие `type`, `name`, `autocomplete`, `inputmode` и ограничения ввода.
- Связанные поля объединяй через `fieldset` и `legend`, когда это помогает понять структуру формы.
- Не используй `placeholder` вместо подписи поля.
- Текст ошибки связывай с полем через `aria-describedby`, а невалидное состояние отмечай `aria-invalid="true"`.
- Ошибка должна объяснять проблему и способ исправления, а не только менять цвет рамки.

## 1.7. Доступность и интерактивные состояния

- Сначала используй возможности нативного HTML. Добавляй ARIA только тогда, когда нужную семантику нельзя выразить нативным элементом.
- Не дублируй и не переопределяй встроенную роль элемента без причины.
- Все интерактивные элементы должны работать с клавиатуры и иметь заметное состояние фокуса.
- Не используй положительные значения `tabindex`. Допустимы только `0` и `-1` для обоснованного управления фокусом.
- Сохраняй логичный DOM-порядок. Не исправляй порядок чтения только визуальной перестановкой через CSS.
- Для раскрывающихся элементов синхронизируй видимое состояние с `aria-expanded`, а переключатели — с `aria-pressed` или нативным состоянием поля.
- Динамические сообщения, которые должны быть озвучены, помещай в подходящую `aria-live`-область.
- Закрытые слои и модальные окна скрывай визуально и одновременно исключай из скринридера и фокуса через `aria-hidden="true"` и `inert`.
- При открытии модального окна снимай закрытое состояние и `inert`, устанавливай `aria-hidden="false"`, переноси фокус внутрь. При закрытии возвращай фокус на вызвавший элемент; поддерживай закрытие клавишей `Escape`.

```html
<div class="modal" aria-hidden="true" inert>
    <!-- Содержимое модального окна -->
</div>
```

## 1.8. SEO и метаданные

- У каждой самостоятельной страницы должны быть уникальные и содержательные `title`, `description` и `h1`.
- Текст ссылки должен объяснять назначение перехода без опоры на окружающий контекст. Избегай повторяющихся формулировок вроде «Подробнее» без доступного уточнения.
- Не скрывай значимый текст от пользователя ради поисковой оптимизации.
- `canonical`, Open Graph, Twitter Cards и структурированные данные добавляй только при наличии требований проекта и заполняй реальными данными страницы.
- Структурированные данные должны соответствовать видимому контенту и проходить профильную валидацию.

## Проверка разметки

- Проверь валидность HTML, корректность вложенности и отсутствие повторяющихся `id`.
- Проверь структуру страницы: `lang`, один `main`, основной `h1`, последовательность заголовков и подходящие семантические элементы.
- Проверь все изменённые классы на соответствие БЭМ и `kebab-case`, состояния — на префикс `is-*`, JS-хуки — на использование `data-*`.
- Проверь порядок и перенос атрибутов, четырёхпробельные отступы и отсутствие лишних контейнеров.
- Проверь каждый `img`: наличие корректного `alt`, размеры `width` и `height`, уместность `loading="lazy"`.
- Проверь SVG: спрайтовые иконки используют `<use>` с корректным `href`, декоративные элементы скрыты через `aria-hidden="true"`, у значимых иконок есть доступное имя.
- Проверь формы: видимые подписи, связи `for`/`id`, типы полей, `name`, автозаполнение, сообщения ошибок и ARIA-связи.
- Проверь доступные имена ссылок, кнопок, навигации и других интерактивных элементов.
- Пройди интерфейс только клавиатурой: порядок фокуса должен быть логичным, фокус — видимым, все действия — выполнимыми.
- Проверь раскрывающиеся элементы и модальные окна: `aria-expanded`, `aria-pressed`, `aria-hidden`, `inert`, управление фокусом и закрытие через `Escape` должны соответствовать видимому состоянию.
